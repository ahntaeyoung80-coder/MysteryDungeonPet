## 점검 결과·변경

기존 구현에는 역할 ID와 배우 instance ID가 있었지만 초상화 clip1/2/3/4가 역할에 고정되어 있었다. 몸체만 교체하면 이전 캐릭터의 초상화가 남을 수 있어 안전하다고 보고하지 않았다.

- `dialoguePortraits`는 현재 화자의 역할/instance만 반환한다. 듣는 사람의 초상화는 그리지 않으며 주인공은 왼쪽, 상대는 오른쪽에 표시한다. `나 · 이상해씨`, `동료 · 파이리`, `NPC · 켈리몬`, 알람의 노공룡처럼 이름표로 구분한다.
- 초상화와 이름표는 기존 대화창의 원작8px nine-slice를 재사용한다. 별도 노란/회색 강조 테두리를 제거하고56×56 원작 프레임 안에40×40 원본 그림을 둔다. 텍스트 영역 y144 아래는 침범하지 않는다. GDI 이름 글자의 alpha도 별도 복구한다.
- 역할과 캐릭터 종류를 분리했다. `cast.json`에는 역할별 몸체 경로만, `characters.json`에는 원본 ROM/판본/MD record별 KAO/이름을 둔다. 생성기가 실제 몸체 package의 source ID를 읽어 ROM hash+판본+MD ID를 만들고 초상화/이름을 결정한다. 역할별 KAO 번호를 복사해 재사용하지 않는다.
- 새 `cast.mddc`에서 플레이어/동료/우호 몸체와 초상화/이름을 함께 선택한다. body assetKey·atlas SHA-256과 portrait character ID를 검사한다. 파일을 다른 캐릭터로 교체하거나 이름만 같은 assetKey로 바꾸어도 다른 atlas를 허용하지 않는다. 알람도 같은 검증을 사용한다. 미등록 캐릭터·누락 역할·잘못된 ROM/조합은 명시 오류이며 이전 얼굴 fallback은 없다. 기존 탐험 저장과 instance/action ID는 바꾸지 않았다.
- 미래 변경은 필요한 원작 동작을 갖춘 몸체 패키지와 확인된 캐릭터 매핑을 준비하고 cast를 재생성하는 방식이다. 선택 UI나 hot swap을 추가한 것으로 표현하지 않는다. [직접 수정 안내](../../QUICK_EDIT_GUIDE.md)의 변경 절차를 갱신했다.

## 검증

Linux의 dialogue portrait·entry/social 관련2/2, Python 캐릭터 ID 생성 회귀4/4, Wine10의 GDI 대사7장면+역할/이름표2개가 통과했다. 신규 회귀는 화자 instance 구분·듣는 사람 미표시·원작 모서리/변 타일·잘못된 조합 거부를 검사한다. 플레이어/동료 몸체 경로만 교환해 얼굴/이름/캐릭터 ID가 함께 바뀌고, 두 역할을 같은 캐릭터로 지정해도 역할은 유지됨을 확인했다. 몸체 assetKey를 재명명해도 atlas hash가 다른 조합은 거부한다.

최종 MinGW GCC14.2 static x64 새 PE를 Wine10/Xvfb에서 실행했다. NPC 양쪽 발화·동료 양쪽 발화·취침·아침·알람의7장면과 실제 플레이어/동료 교환 후2장면, 총9개 캡처에서 단일 화자·원본40×40픽셀·원작 프레임/이름표 테두리를 대조했다. 바뀐 몸체 경로만 지정한 생성 결과가 실제 EXE의 교체 cast와 일치함을 확인했다. NPC/동료/교환 시나리오의 대화 중 위치/라운드 정지와 탐험 재개도 유지했다. Wine의 외부 unlock 도우미와 registry 글꼴 대체는 검사 환경에만 적용했고 제품 Windows 정책/맑은 고딕 설정은 유지했다. native Windows/사용자 Windows11은 pending이다.

구현 중 C++ 공개 함수 변경에 따라 기존 양쪽 표시 검사를 새 화자 단독 검사로 갱신했다. atlas hash 검증을 추가한 뒤에는 해당 ID/로드 검사와 새 PE 장면을 다시 확인했다. 저장/탐험 공통 로직은 수정하지 않아 전체 메모리 검사는 실행하지 않았다. 기록 추가만으로 통과한 코드 전체 검사를 반복하지 않는다.
