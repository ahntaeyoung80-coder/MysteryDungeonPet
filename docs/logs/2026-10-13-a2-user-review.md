## 확인된 문제

1. **방향·프레임 관찰 정보 부족.** CSV에는 animation ID/direction/frame/장면 좌표가 없다. `switch_count=100`은 전환 횟수만 증명하며 8방향의 선택·재생·좌표 이동을 기록만으로 판정할 수 없다. 실제 창 위치도 모든 측정 실행에서 고정되어 있지만 이는 드래그 기록이 아니라 자동 시나리오다.
2. **종료 시 측정 오류.** 각 CSV의 종료 전에는 DPI96/위치(1766,726)가 유지되다가 마지막 행만 DPI0/위치(0,0)가 된다. `WM_CLOSE`에서 창을 파괴한 후 run 끝의 `sample()`이 창 정보를 조회한다. 실제 창이 원점으로 이동했다는 증거가 아니다. CPU·메모리 측정과 창 정보의 유효성을 구분해야 한다.
3. **순수한 빈 창 기준선이 아님.** empty에서도 Walk와 같은623 marker가 발생한다. 화면만 비우고 Animator/deadline 처리는 계속하므로 빈 창의 CPU 비교 기준이 오염된다. 렌더 제출1회는 정상적으로 억제됐다.
4. **합성 시험 자산의 표현 한계.** v1은 방향/frame마다 색을 바꾸며 같은 원형 geometry를 사용하고 검정 pixel 위치만 바뀐다. 몸체 위치는 고정된 채 clip을 제자리 재생한다. 색 변화는 의도된 값이나 이를 실제8방향 움직임 확인용으로 안내한 것은 부정확했다. 이 관찰만으로 방향 resolver의 결함을 판정하지 않는다.
