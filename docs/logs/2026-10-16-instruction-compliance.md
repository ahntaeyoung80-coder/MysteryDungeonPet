## 실제 검사 경로에서 확인한 점

[일반 CI](../../.github/workflows/a2.yml)는 모든 push/PR에 전체 Windows/Linux 검사를 실행한다. [작업 브랜치 CI](../../.github/workflows/party-ai-runtime.yml)는 같은 브랜치 push에서 별도로 실행되며 소규모 preflight 뒤 Windows→Linux를 순차 실행한다. 따라서 preflight가 있어도 일반 CI의 전체 작업이 함께 실행될 수 있다. 향후 검증 경로를 정할 때 자동 트리거와 중복 실행부터 확인해야 한다.

이번 점검에서 과거의 모든 전체 검사 재실행을 개별 판정하거나 불필요한 시간의 합계를 산출하지는 않았다. 실제로 수행하지 않은 비용 분석을 완료했다고 보고하지 않는다.

## 이번 수정

루트 [AGENTS.md](../../AGENTS.md)에 기존 규칙을 실행 전·실행 중·마감의 확인 절차로 연결했다.

- 사용자 재요청 없이 착수/재개 시 확정 범위·기존 결과를 확인하고, 실제 수정/검사 전 범위·항목/단계별 예상·검사 순서를 보고한다.
- 영향받는 소규모 검사 → 실패한 관련 검사로 수정 확인 → 변경을 모은 뒤 통합검사를 기본 순서로 둔다.
- 전체 검사에는 영향 범위·필수 CI·통합/배포 등 실행 근거를 남기며, 자동 트리거 중복도 먼저 확인한다. 제약으로 전체 검사가 필요하면 이유와 추가 예상 시간을 실행 전에 알린다.
- 같은 코드의 통과 결과를 재사용하고 문서만 변경하면 문서 검증으로 끝낸다. 필수 최종 검증은 유지한다.
- 예상 초과/범위 변화는 먼저 보고하고, 마감 전에 사전 보고·재실행 근거의 누락을 스스로 확인한다. 사용자에게 검사 여부의 기술 판단을 전가하지 않는다.

이 변경은 지침과 이 점검 로그2파일뿐이다. 소스·자산·EXE·CI workflow는 수정하지 않았다. workflow 최적화까지 구현했다고 보고하지 않는다. PROJECT_STATE에는 이 과거 경위를 누적하지 않는다.
