# 오랭열매 소지·사용 검증 — 2026-10-23

사용자 확정 규칙은 **플레이어 최대 1개, 동료 최대 1개**다. 사용하면 해당 배우의 열매는 0개가 된다.

앞선 검사는 “재고를 소비하는가”만 확인해 유한 재고가 줄어드는 결과를 얻었지만, 각자 최대 99개까지 쌓이던 소지 규칙의 오류를 놓쳤다. 이번에 소지 한도를 1개로 고쳤다. 이전의 3개씩/총 6개 사용 검사는 현재 규칙의 근거로 사용하지 않는다.

## 현재 동작

- 오랭열매는 각자 0개 또는 1개만 가진다. 플레이어와 동료의 슬롯은 별개다.
- 획득 시 빈 슬롯에 1개만 배분한다. 둘 다 빈손이면 체력이 더 낮은 동료를 먼저 주고, 그 외에는 플레이어가 먼저 가진다. 한쪽만 소지 중이면 빈손인 배우에게 준다.
- 둘 다 소지 중이면 추가 열매를 줍지 않고 바닥에 남긴다. 획득 메시지·누적 획득 기록도 만들지 않는다. 사용해서 빈 슬롯이 생기면 남은 열매를 다시 목표로 삼을 수 있다.
- 하트가 1~3이고 열매가 있으면 1개를 소비해 최대 5하트로 회복한다. 소유한 배우와 무관하게 체력이 부족한 팀원이 사용할 수 있다. 자기 열매를 먼저 먹고, 없으면 상대의 열매 하나를 사용한다. 사용한 슬롯은 0개가 된다. 저장 복원으로 다시 지급하지 않는다.
- 물물교환은 플레이어 슬롯이 비어 있을 때 사과 3개로 열매 1개를 받는다. 슬롯이 찬 거래는 사과도 소비하지 않는다.
- 나눠 주기는 둘 다 열매가 있어서 팀에 하나를 남길 수 있을 때만 한다. 체력이 더 높은 배우가 자기 1개를 건네고, 체력이 같으면 플레이어가 준다. 팀에 마지막 하나만 남았다면 격려 대사로 진행한다.
- 기존 저장의 누적 수량 2~99개는 불러올 때 각자 최대 1개로 맞춘다. 0개는 0개로 유지한다. 원래 유효 범위보다 큰 값은 손상된 저장으로 계속 거부한다. 날짜·획득 이력·진행·다른 아이템은 보존하며 저장 형식은 바꾸지 않았다.
- 일반 원정층의 보장 공급과 기존 무작위 출현표는 유지한다. 더 많이 나와도 소지 한도는 각자 1개다. 누적 획득 이력(`inventory`)은 현재 소지 수량이 아니다.

## 검증

| 검사 | 결과 |
| --- | --- |
| 단독/독립 파티 × 두 배우의 0/1 소지 조합 | 빈 슬롯에만 1개 지급, 두 슬롯 모두 1이면 바닥 열매 보존 |
| 실제 획득 후 저장·복원·재갱신 | 중복 지급 없음 |
| 플레이어 1개·동료 1개로 반복 부상·매 갱신 저장 복원 | 합계 2개만 사용, 이후 0개에서 추가 회복 없음 |
| 기존 MDES18의 99개·2개 입력 | 각각 1개로 복원, 다시 저장·복원해도 1개 |
| 기존 유효 범위를 넘는 100개 입력 | 거부 |
| 물물교환·나눠 주기·예약·전투·다음 날 재고 유지 | 1개 규칙과 실제 소모/안전한 퇴각 유지 |
| 새 Windows EXE 화면 3건 | 두 슬롯이 찼을 때 획득 없음, 빈 동료에게 지급, 사용 후 두 슬롯 0 확인 |

관련 코어 8개를 확인했다. 최초 전투 검사 하나는 이전 5개씩 소지한 승리를 전제로 해 실패했다. 현재 조건에서 정상 퇴각한 것을 확인한 뒤, 검사를 1개 소지 상태의 승리·안전한 퇴각을 모두 검증하도록 수정하고 해당 검사만 재실행해 통과했다. Windows PE 검사 2개도 Wine에서 통과했다. [상세 로그](../logs/2026-10-23-single-berry.md), [결과](../validation/2026-10-23-single-berry/summary.json).

회복 메시지는 `오랭열매를 먹었다.`만 출력한다. 화면의 재고 설명은 제거했고 추적 CSV의 `player_oran`, `companion_oran`은 개발 검증용 0/1로 유지한다. 실제 Windows 11 장기 실행은 미검증이며 화면 검사는 Wine10/Xvfb와 합성 잠금 해제를 사용했다.

후속 검증: 자기 열매가 없는 플레이어/동료가 상대의 1개를 소비해 회복하는 양방향을 legacy·독립 파티에서 확인했다. 재고의 소지 한도는 여전히 각자1개다.
