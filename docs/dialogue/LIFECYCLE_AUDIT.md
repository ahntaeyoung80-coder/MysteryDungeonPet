## 재현해 수정한 정체

1. **없는 동료를 기다림.** BedFace/BedLay/Sleeping/Waking/MorningFace는 `player && partner`를 무조건 요구했다. 동료가 꺼진 정상 상태에서 `ActorCompletion{true,false,false}`로 진행하면 기상 또는 저녁에 정체했다. 필요한 배우의 완료만 확인하도록 수정했다.
2. **유한 장면에 무기한 대기.** BedFace/BedLay/MorningFace/RoomExit와 기본 대화는 deadline 이후에도 완료가 없으면 계속 기다렸다. Waking에도 완료 통지 누락 시 탈출 조건이 없었다. 최소 시간과 유한 동작을 구분하여 Waking은 기존 유한 deadline, 나머지는 읽기/장면 deadline 뒤 5초의 유예에서 진행하게 했다. 정상 완료 통지가 오면 기존 시점에 진행한다. 카탈로그 대사의 기존 읽기 시간+6초 유예는 유지했다. 전투 타격 완료 조건에는 이 유예를 적용하지 않았다.

새 저장 필드는 필요하지 않다. 기존 MDES1~20의 deadline·배우 사용 여부를 재사용한다. 과거 저장을 삭제하지 않고 복원할 수 있다.

## 중복 소비와 종료 위험 판정

- 새로 확인된 중복 소비 버그는 없었다. 획득의 onceKey, 열매 자기 슬롯 우선/상대 슬롯 대여, 공유·교환의 예약과 committed 키, 당일 mealCommitted를 추적하고 기존/추가 회귀로 재확인했다.
- 나눔은 팀에 열매를 하나 남길 수 있을 때만 예약하며, 결과 경계에서 소유자의 열매 하나만 준다. 결과 확정 전 취소는 예약만 해제한다. 이미 준 상태를 저장·복원한 뒤 같은 결과 함수를 다시 호출해도 추가 차감하지 않는다.
- 교환은 원본 공급 표에 열매가 있고 플레이어 슬롯이 비었을 때만 사과3개→열매1개로 확정한다. 검사에서는 공급을 열매로 고정한 합성 표를 써서 확정 경계 자체를 반복 검증했다. 실제 일반 공급 확률을 변경하지 않았다.
- 일반 EXE는 candidate를 만들어 저장에 성공한 뒤 현재 상태와 화면 이벤트를 교체한다. Windows 저장은 같은 경로의 임시 파일→flush→원자 교체이며 `.tmp`를 정상 저장으로 불러오지 않는다. 디스크/파일 권한 오류·손상된 저장·지원하지 않는 자산 버전·카운터/저널 상한은 계속 명시 오류로 거부한다. 이를 정상 생활 흐름의 종료 버그와 섞어 기록하지 않았다.
- 사과/일반 도구 재고 상한과 누적 기록/파일 크기 상한은 남아 있다. 이번 검사는 임의로 긴 무한 운영이나 모든 실제 Windows 장애의 복구를 보장하지 않는다. 검사한 일반 흐름에서 새 예외 종료는 발견하지 못했다.

## 검증 근거와 범위

`tests/lifecycle_audit_tests.cpp`는 단독 배우·완료 누락·기본 대화·기상부터 다음 날까지 매 단계 저장 복원·나눔/교환 재확정의 5그룹을 실행한다. 수정 전에는4그룹이 실패했고 수정 후67검사가 통과했다. 같은 회귀의 ASan/UBSan과 Windows PE도 통과했다.

관련 생활/동료/대화/귀가/원정/휴일/재고 검사14개를 실행했다. 이전 검사 일부에 동료 미활성 fixture, 과거32px 패널 하단 좌표가 남아 있어 보정하고 실패 검사만 재실행해 통과했다. 조용한 플레이어 화면에는 GDI 글자0개를 요구하도록 검사도 맞췄다. 최종 결과·EXE 화면 확인은 작업 로그의 결과 파일을 따른다.

실제 Windows EXE의 단독/동료 동반2건은 취침 저장에서 눕기→수면→기상→퇴실→다음 날 모험에 진입했다. 최종 저장은 모두 day2·식사1회이며 scene0의 탐험 상태다. Wine10/Xvfb·한글 대체 글꼴·합성 WTS 해제를 사용했다. 실제 Windows11·장기 운영·자연 전투로8개 원정을 모두 승리한 검증은 아니다.
