## 우선 개선할 협동 전투

일렉트릭 평원은 고정 보스방에 적9명, 바닷가 동굴은3명이 있고 현재 모두 보스 판정4하트다. 바닷가 동굴seed42는 플레이어·동료가5/5로 입장해 플레이어0·동료5로 패배했다. 추적에서 동료는 이동했고, 첫 적 옆 공격 위치를 잡기까지3라운드가 걸리는 동안 적이 플레이어를 집중 공격했다. 동료가 정지하거나 체력이 낮아서 생긴 문제로 단정할 수 없다.

측정 도구 내부에서만 주 보스4하트를 유지하고 이 두 원정의 보조 적을2하트로 바꿨다. 동행8건의 두 원정 결과는 여전히 각각0/4였다. 따라서 보조 적 체력만 낮추는 제품 변경은 하지 않았다. 기본 설정의 원자료와 가설 자료를 섞지 않는다.

다음 제품 작업 우선순위는 **동료의 실제 접근 가능한 공격 칸을 고려한 대상 선택·초기 합류**, 이어 **다수 적의 동시 교전 수/등장 순서**, 그다음 **긴 원정의 회복 공급과 구간 길이**다. 보스4하트·열매각1개의 확정 계약은 유지한다. 같은seed로 전후 비교해 동료 첫 공격까지의 라운드·양쪽 피해 분담·클리어와 원정 길이를 평가해야 한다. 현재 점검은 이 설계 변경을 구현한 것이 아니다.

## 실행 관측과 성능

실제 EXE30분은 프로세스 경과1801.78초·앱 계측1800초로 종료 코드0이다.35→17→41→1→21로 원정이 바뀌며 day5·meals4까지 진행했다. 완료된 앞 네 원정은 모두 패배였다. 패배→식사→취침→기상→다음 날은 이어졌으나 이 관측에서 보스 승리/클리어는 확인하지 못했다. 중간 진행 보고의 해안 동굴 클리어 표현은 저장의 Defeat 결과를 대조해 정정했다.

초당 자원1799개·저장156개를 관측했다. 저장 decoder 준비 전 초기 약149초는 저장 표본이 없고 마지막 표본은1793.31초다. 앱 계측은1초부터1800초까지 있다. 표본 열매 상한은 각1이며 실제 모든 프레임/소비를 상세 trace로 확인한 것은 아니다. 이벤트 로그에 새 fatal은 없었다.

Linux Wine10/Xvfb에서 실제 루트 EXE를 실행했다. 상세 frame trace는 끄고 앱 초당 계수·10초 간격 저장 decoder를 사용했다. Wine의 세션 검출 제약 때문에 합성 WTS 해제 도구를2초마다 호출했으며 실제 Windows 잠금/해제 검증이 아니다. 한글 대체 글꼴을 사용했다. [기본 패널 화면](evidence/normal-status-wine.png)에서2줄 크기의 상태창·평시 초상화 없음·짧은 PC 상태를 확인했다. 대사 전체/모든 DPI를 이 한 화면으로 검증하지 않는다.

작업 중 Wine 서비스 `winedevice.exe` 로드 실패 로그는 환경 제약으로 분리한다. 앱 종료 코드·fatal·저장 decoder·화면 진행을 별도로 확인한다. Wine의 private/handle/GDI 계수가0인 것은 미지원이며 누수 없음으로 해석하지 않는다. CPU와 working set도 실제 Windows 목표 판정에 사용하지 않는다. 자산 decode 증가와 메모리 증가의 관계만 관측하며30분 자료로 장기 누수 없음이나24시간 안정성을 주장하지 않는다.

## 도구 검증과 남은 범위

- native Release 측정40건8.38651초, 보조 적 가설10건1.67297초. Windows PE 측정 도구는 같은 바닷가 동굴5건을 Wine에서 실행해 기본 결과와 일치했다.
- 분석기 회귀4개 통과. 일시 정지·긴 관측 공백이 CPU 평균을 희석하지 않도록 하고, 시간 역전/계수 리셋·불완전40건·미지원0계수의 잘못된 합격을 막는다.
- PowerShell7.4.6 구문 검사와 비Windows 실행 거부 확인 통과. UTF-8 BOM·CMD CRLF와 설치본 포함을 확인했다. **Windows 수집기 자체의 네이티브 실행은 미검증**이다.
- CMake 설치 목록 변경 뒤 재설정 전 설치 안내 파일이 빠진 것을 확인해 재설정/재설치했다. 제품 오류가 아니며 최종 설치에는 수집기와 안내가 포함된다.
- 루트/빌드/설치 EXE SHA256은 `bcf3ac8e16b7a8915576a0bb90038e3250e8b681183f10655b5f1cb74704b73e`로 동일하다. CMake 입력 변경만 manifest에 갱신하며 게임 실행물 바이트는 유지한다.

실제 Windows11의30분/2시간·드래그·배율·DPI·잠금·화면 꺼짐·절전/복귀는 남아 있다. [더블클릭 자료 수집](../../QUALITY_CHECK.md)을 제공한다. 원격 전체 CI는 push 후 백그라운드이며 완료 결과를 이 점검에 대신 넣지 않는다. **PC 활동 연동 전 품질 전체 합격은 아직 아니다.** 협동 다수전 개선과 실제 Windows 관측을 우선한다.
