## 2026-10-20 — 화자 한 명·원작 프레임·캐릭터 ID 연결

- 아래 초기 초상화 연출의 양쪽 표시/강조 테두리를 대체한다. 현재 화자 한 명만 주인공은 왼쪽, 상대는 오른쪽에 표시한다. 초상화56×56과 이름표112×24는 텍스트박스와 같은 원작 `frame_b0`의8px 모서리/변/중앙 타일을 사용하며 내부40×40 원본 그림은 유지한다. 이름표는 역할과 실제 캐릭터 이름을 함께 표시한다.
- 역할 `Player/Partner/Friendly/Alarm`(1/2/3/4), 배우 instance(0/예약 동료/NPC instance/알람109), 실제 캐릭터 ID(ROM hash+판본+MD record), portrait clip ID(MD record), 원본 KAO 인덱스를 분리한다. 역할 번호나 atlas 순서로 초상화를 조회하지 않는다.
- `portraits/cast.json`은 역할별 몸체 패키지 선택만 보관한다. `characters.json`은 ROM/판본/MD record별로 검증된 KAO 인덱스와 이름을 보관한다. 생성기는 선택한 실제 몸체의 source MD ID로 초상화/이름을 결정해 `cast.mddc`를 만든다. 런타임의 플레이어·동료 몸체 로드와 초상화·이름 조회는 같은 binding을 사용한다. body assetKey/atlas hash와 portrait character ID 불일치, 미등록 캐릭터는 명시 오류다. 저장의 행동권·instance ID는 캐릭터 종류 변경과 분리해 유지한다.
- 캐릭터 변경은 필요한 원작 동작을 갖춘 몸체 패키지와 검증된 매핑을 준비하고 cast를 재생성/배포하는 경로다. 캐릭터 선택 UI나 실행 중 hot swap은 이번 범위에 포함하지 않는다. 기존 역할 고정 방식의 교체 위험을 발견해 보완했으며 플레이어/동료 교환·동일 캐릭터 두 역할·잘못된 조합의 회귀로 검증한다.

## 2026-10-16 — 독립 배우·경로·관계·7층·최근 지형

- 최단 경로는 이동 수 → 대각선 수 → 고정 부모 tile 순서로 고정한다. 접근/복귀 목표는 거리·대각선·회전·tile로 고른다. gameplay는 이동 결정마다 경로를 재계산해 연속/복원 차이를 없앤다. 전역 최소 회전 경로를 보장하지 않는다.
- 동료 HP는 내부 유지·HUD 숨김. 우호 MD383/sprite556 녹색·적 MD384/sprite554 보라색은 원작 추출 패키지와 저장 관계로 선택한다. renderer가 보고한 자산 이름 대신 fixture 역할과 원본 픽셀로 검사한다.
- 기본 새 탐험은 원본 dungeon15의7층. 기존 dungeon0의3층 저장은 그대로 진행하고 정상 다음날 생성에서만 패키지를 전환한다. 명시 --explore는 지정 출처를 유지한다. 이행 때문에 저장을 삭제하지 않는다.
- 원시 run별 지형 hash에 최근64개 바운딩 박스/0·1마스크 hash를 추가한다. 평행이동 모양 중복을 최대128회 생성 예산 안에서 거부하고 다음날에도 기억을 전달한다. 기존 journal을 사용하며 구형 저장은 보존된 현재 지도부터 이어간다. 개별 방 크기 유사성과 사용자 미확보 장면의 해결까지 보장하지 않는다.

아래 날짜별 결정은 당시 이력이며 위 결정과 후속 사용자 요구가 우선한다.

## 2026-10-23 — 오랭열매는 배우마다 하나만 소지

사용자가 1인당 열매 1개·사용 후 소멸을 확정했다. 일반 재고 상한99를 오랭열매에 적용했던 것을 바로잡아 별도 한도1을 사용한다. 획득 시 빈 배우에게만 지급하고 둘 다 소지 중이면 바닥에 남긴다. 지급은 실제 획득 경계에서 한 번만 하며 legacy/독립 파티의 후속 처리에서 다시 더하지 않는다. 교환은 플레이어 슬롯이 비어 있을 때만 하고, 나눠 주기는 팀에 열매 하나가 남을 때만 한다.

MDES1~18을 계속 읽고, 기존2~99개 누적 재고는 각자1개로 정규화한다. 0개는 유지한다. 현재 저장 쓰기·검증은 한도1을 강제한다. 날짜·과거 획득·타 아이템·원정 진행을 바꾸지 않는다. [현재 검증](dialogue/ORAN_AUDIT.md).

## 2026-10-23 — 간단한 출력·팀 열매·보스와 친구 되기

사용자 지시로 적 처치 알림·화면 재고·PC 행동 접미사를 제거한다. 회복 문구는 `오랭열매를 먹었다.`다. 각자 최대1개를 소지하고 자기 열매를 먼저, 없으면 상대의 열매를 사용한다. 재고가 없을 때의 도주·사건 철수 판단도 팀 전체를 확인한다.

아이템156개에 반응3개씩 총468개를 작성했다. 원문은 `assets/original/gameplay/dialogue/item_comments.json`, 생성 표는 `src/core/item_comments.inc`이며 `python -m tools.compile_item_comments`로 재생성한다. 선택은 대사 RNG에서만 하고 최근 같은 아이템 반응을 피한다. MDES19가 선택된 반응 번호를 기존 블록 뒤에 저장한다. MDES1~18을 계속 읽으며 기존 반응의 기본값은0이다.

최종 고정층에서 마지막 보스의 기절 재생이 끝나면 적대를 해제하고 대표 보스·동료의 대화8묶음 중 하나를 진행한다. 대화가 끝나면 친구 기록을 커밋하고 중앙 클리어·귀가로 이어진다. 친구 기록은 기존 gameplay onceKeys에 종별 키로 저장해 다음 날에도 복사한다. 대화 중 저장은 선택된 줄·남은 시간을 그대로 복원한다. 다수 보스는 모두 친구 상태로 표시하고 중앙 도착을 가로막지 않게 자리를 정리한다. 보스가 없는 층은 기존 중앙 클리어를 유지한다.

## 2026-10-23 — 보스4하트와 입장 전 준비 대사

사용자 요청으로 고정층의 적대 보스 출현(spawnType7/10 제외)은4하트로 생성한다. 일반 적·중립 NPC는2하트를 유지한다. 원본 지형·출현표는 바꾸지 않고 제품 정책으로 적용한다. 캐시·저장·검증의2하트 상한을 보스에 한해 확장한다.
