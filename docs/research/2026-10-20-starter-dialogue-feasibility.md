# 층수 HUD·대화 방향·사망 대사·스타팅 교체·감정 초상화 검증

2026-10-20 KST. 검증 기준 work `da2d06fa1e9e4c955623e794ae60164b51cdb658`. 사용자의 “지금은 코드 수정하지 말고 검증만” 지시를 적용했다. 제품 소스, 설정, 배포 에셋과 EXE는 수정하지 않았다. 임시 변환물은 `/workspace/scratch/starter-audit/`에만 생성했고 이 문서와 검증 증거만 저장한다.

요청한 기능은 현재 C++/Win32 구조로 구현 가능하다. 스타팅 선택에 필요한 원작 몸체와 일반 감정14종은 모두 확보 가능하다. 추가 대조에서 현재 켈리몬 몸체(MD383)에 릴리요 초상화(KAO373)를 잘못 연결한 기존 결함을 발견했다. 정확한 원작 켈리몬은 KAO382이며 기본·화남·슬픔3종이 있다. NPC까지 전 감정을 표시하려면 별도 보완 후보 또는 기본 표정 대체 규칙이 필요하다. 실제 설정 메뉴·페이드 수정·사망 대사·감정 선택 기능을 구현한 것으로 보고하지 않는다.

## 3. 몸체 변환과 필수 동작 검증

선택 대상의 원작 `MONSTER/monster.bin`, `m_ground.bin`, `m_attack.bin`을 기존 파서로 읽고 병합했다. Walk0, Attack1, Sleep5, Hurt6, Idle7, EventSleep13, Wake14, Eat15, Pose17, Nod22, Laying27, Faint33, HitGround34의13동작 모두 방향/프레임/시간 데이터가 있었다.

기존 export→packer→MDPA 경로를 그대로 호출해 **22개 임시 패키지 전부** 만들었다. 직접 원작 WAN 그림과7,671개 변환 프레임, 병합 전 원본11,679개 비교가 통과했다. 기존 native `pet_package_inspect`도22개 모두 읽었다. 원본 그림·anchor·marker·shadow·tick 비교가 포함되며 임의 Idle 대체로 누락을 숨기지 않았다.

임시 패키지의 PNG 합548,324bytes + MDPA 합3,364,427bytes, 한 몸체의 최대 decode752,640bytes였다. 기존 단일 atlas8MiB 제한 안에 들어간다. 메뉴를 위해 전 캐릭터를 메모리에 상주시킬 필요는 없으며 선택한 두 배우와 필요한 NPC만 로드하면 된다. 이 수치는 이번13동작 프로토타입의 측정값이고 제품 설치 용량·전체 Windows 메모리 예산을 최종 검증한 것은 아니다. 모든 스타팅의 실제 Windows WIC/장기 실행은 구현 후 검증 범위다.

## 4. 감정 초상화

`FONT/kaomado.kao`의 원본40×40 그림을 전체 후보에 대해 읽었다. 모든21종에서 아래14종이 실제로 존재했다. 성별34개 MD는 검증된 종별 얼굴을 공유할 수 있다.

| --- | --- | --- | --- |
| 0 | NORMAL | 0 | 기본 |
| 1 | HAPPY | 2 | 기쁨/인사 |

감정 ID와 KAO subindex는 다르다. `subindex=감정ID×2+반대방향slot`이며 짝수 칸이 일반 그림이다. 불꽃숭이는 원작의 반대방향 칸도 있지만 대부분 종의 홀수 칸은 비어 있다. 없는 칸을 다른 감정으로 잘못 해석하지 않아야 한다. 원작 FAINT 초상화는 어지러운 얼굴이며 몸체 동작 Faint33과 별개다. 대사 분위기에 맞는 걱정/슬픔/외침을 지정하고 몸체 기절 ID를 초상화 ID로 재사용하지 않는다.

추가 ACTION1/2 등도 있지만 현재 요구에는14종으로 충분하다. [감정 전수 대조표](../validation/2026-10-20-starter-dialogue-audit/starter-expressions.png)를 참고한다.

현재 NPC 초상화 세트의 실재 범위는 다음과 같다.

- **확인된 기존 결함:** `characters.json`은 녹색 켈리몬 몸체 MD383(dex352, sprite556)에 KAO373을 연결한다. KAO373은 MD374/dex346인 릴리요의 기본 얼굴이다. 기존 수동 시각 분류가 잘못됐으며 현재 cast의 자체 일관성 검사만으로는 이 오류를 찾지 못한다. “켈리몬은 표정 한 장뿐”이라는 중간 보고도 이 잘못된 세트에 대한 결과여서 정정했다.
- **정확한 녹색 켈리몬은 KAO382:** subindex0/6/10, 즉 기본·화남·슬픔3종이다. SpriteCollab 켈리몬 Normal의 RGBA도 KAO382와 byte-identical이었고 현재 잘못된 KAO373과는 달랐다. [오류/정상 얼굴 대조](../validation/2026-10-20-starter-dialogue-audit/npc-mapping-defect.png), [ID/픽셀 증거](../validation/2026-10-20-starter-dialogue-audit/npc-mapping-defect.json). 다음 구현 때 카탈로그373→382 수정과 실제 원본 얼굴 회귀가 우선이다. 사용자 지시대로 이번에는 해당 제품 파일을 수정하지 않았다.
- 노공룡 MD322→KAO321: subindex0/2/4/6/20/24/32/34/36. 일반 감정은 기본·기쁨·아픔·화남·크게 기뻐함·놀람이며, 외침14 등은 없다. 알람 분위기는 실제 있는 화남6 등으로 지정하거나 별도 보완 후보를 써야 한다.
- 누락 감정은 명시적으로 기본 표정으로 대체하고 감사 기록에 남길 수 있다. 모든 NPC가 모든 감정을 원작 그림만으로 표시할 수 있다고 보고하지 않는다.

보완 에셋 후보는 기존 조사에서 고정한 [PMDCollab/SpriteCollab](https://github.com/PMDCollab/SpriteCollab/tree/e4b1949687cb2344e6675717466e357189d3acba/portrait)에서 찾았다. [켈리몬0352](https://github.com/PMDCollab/SpriteCollab/tree/e4b1949687cb2344e6675717466e357189d3acba/portrait/0352)와 [노공룡0294](https://github.com/PMDCollab/SpriteCollab/tree/e4b1949687cb2344e6675717466e357189d3acba/portrait/0294)에 Happy/Worried/Sad/Angry/Shouting 등 파일과 credits가 있다. 켈리몬 credits는 CHUNSOFT 그림과 추가 기여자 그림을 구분하며 CC_BY-NC_4를 명시한다. 노공룡 추가 표정에는 PMDCollab_1 표기가 있어 파일별 출처/조건을 보존해야 한다. 두 후보의 Normal/Happy/Worried/Sad/Angry/Shouting12개 파일을 실제로 읽어 전부40×40인지 확인했다. 노공룡 Normal도 현재 원작 KAO321과 byte-identical이었다. [후보 파일·hash·원본 일치 결과](../validation/2026-10-20-starter-dialogue-audit/external-candidates.json). 이번에는 후보 대조만 수행하고 제품 에셋으로 채택하지 않는다.

## 5. 서로 바라보기 검증

기존 core 라이브러리를 연결한 임시 probe에서 NPC/동료 대화 × 단독/독립 파티 경로 ×8방향의32시나리오를 실행했다. 플레이어 발화와 상대 발화 각각 저장→복원 뒤 방향을 확인한 **64상태가 통과**했다. 현재 대화 시작 코드는 플레이어→상대, 상대→플레이어 방향을 이미 지정한다.

기존 최종 EXE의 NPC 대화105개 trace 샘플도 플레이어2(오른쪽), NPC6(왼쪽)으로 서로 보는 값이었다. 이번 검증에서는 사용자가 본 방향 오류를 재현하지 못했으며 전체8방향의 새 Windows 화면 검증을 했다고 주장하지 않는다. 구현 시 실제 인수 기준은 입장/응답/복원 모두 두 배우의 실제 표시 방향 일치다. NPC와 대화 중 옆에 서 있는 동료를 추가 청자로 돌리는 요구는 플레이어↔대화 상대의 방향과 별도로 다룬다.

## 6. 사망 대사와 이후 랜덤 대사를 위한 연결

새 원작 그림은 필요 없다. 기존 원작 대화창·동료 역할·검증된 감정 초상화를 재사용하면 된다. 다만 현재 Death의 panel 제외 조건과 화자 없음, 짧은 자동 fade를 함께 보완해야 한다.

현재 단계에서 필요한 데이터는 `event/context ID`, `line ID`, `speaker role`, `text`, `emotion ID`, `읽기 시간`이다. 지금은 상황당 고정 문구 한 개로 출력할 수 있게 하고 이후 후보 목록을 늘리면 된다. 렌더 함수가 문자열에서 감정을 추측하거나 매 프레임 문구를 다시 뽑는 방식은 피한다.

선택된 대사 ID와 감정/화자를 장면 시작 때 고정하고 저장·복원한다. 이후 무작위 선택을 넣을 때 전투/지도 RNG를 소비하지 않는 대사 전용 선택 경로를 둔다. 같은 사망/귀가 사건이 복원 뒤 다시 대사·피해·식사를 중복 발생시키지 않아야 한다. 주인공 기절과 동료 기절은 HP/숨김 상태가 다르므로 각각의 대사 context를 둔다. 동료 자신이 기절한 경우에도 동료의 마지막 대사를 요구한다면 다운된 상태의 말로 정의할 수 있으며, 이 세부 문구/화자 정책은 아직 확정 구현하지 않았다.

DeathStage는 현재 FadeOut/Blackout 두 값만 허용하고 MDES10 로더도 범위를 검사한다. 대사 단계를 추가하면 저장 스키마/범위와 구형 저장 이행도 함께 확장해야 한다.

## 7. 우클릭 캐릭터 교체에 필요한 연결

기존 역할별 몸체/초상화 binding 구조는 재사용 가능하지만 위 켈리몬의 잘못된 수동 매핑을 먼저 바로잡아야 한다. 메타데이터끼리 일치한다고 실제 그림의 종도 맞는 것은 아니므로 원본 종/그림 대조를 별도로 유지한다. 다만 현재 catalogue에는4캐릭터만 들어 있으므로 스타팅 전체 ID·표정 목록을 추가하고, 주인공/동료 선택 설정을 cast 로드보다 먼저 읽는 경로가 필요하다.

- 메뉴는 표시 이름과 선택 상태를 보여주고 실제 설정에는 ROM hash+판본+MD ID를 저장한다. `player=0`/`companion=UINT32_MAX-1`인 행동 instance와 실제 캐릭터 종류를 분리한다. NPC 관계/던전 ID와 섞지 않는다.
- 메뉴 ID→허용 catalogue 항목으로 바인딩하고 임의 MD/파일 경로를 그대로 받지 않는다. 같은 종을 두 역할이 골라도 역할 instance와 HP/진행은 별개다. 원작의 동일 타입 파트너 제한까지 추가하는 것은 이번 요청으로 확정된 범위가 아니다.
- 교체 후보의 원본/필수 clip/초상화 ID를 먼저 검사한다. 활성 Animator가 이전 Package를 참조하므로 정지·재연결 후 몸체와 초상화를 함께 교체한다. 실패하면 이전 정상 선택을 유지한다.
- 이동/공격/대사 도중에는 선택을 예약하고 안전한 행동 경계에 적용하는 방식을 권장한다. 이때 체력·아이템·날짜·현재 층을 초기화하거나 추가 행동권을 주지 않는다.
- 현 `window.state`는 위치/배율만, MDES10은 탐험 상태만 저장한다. 사용자 캐릭터 profile은 별도 버전 설정으로 저장하는 경로가 필요하다. 앱 재시작·길드/취침/사망/원작 정상·명시 복원에서도 같은 설정의 몸체/초상화가 유지되는지 확인해야 한다.

## 8. 다음 구현의 검증 범위

실제 구현 시 먼저 관련 검사로 층수만의 위치·최종 fade0/중간/끝, 대화8방향/복원, 사망 대사1회·귀가, 역할별 허용/금지 캐릭터·설정 재시작, 기본/감정/누락 감정 대체를 확인한다. 이어 실제 EXE에서 NPC·동료 대화, 양쪽 기절, 메뉴 교체, 귀가·식사·취침·기상·정상을 실행한다. 전체 메모리/통합 검사는 이번 조사에서 실행하지 않았고 제품 코드 수정 없이 기존 검사·native 로더·오프라인 원본 검증만 사용했다.
