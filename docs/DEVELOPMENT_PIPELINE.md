## 2. 최종 목표와 구현 제약

『포켓몬 불가사의 던전: 하늘의 탐험대』 기반 Windows 데스크톱 펫을 만든다. 200×200 실제px로 고정한 작은 창 안에서 원작 캐릭터가 자율 탐험하고, 친구를 만나고, 아이템을 얻고, 계단을 통해 이동한 뒤 귀가·식사·수면·기상한다. 사용자의 PC 활동은 생활 리듬과 연출에 간접적으로 반영한다.

- 원작 데이터·그래픽·애니메이션과 기존 파서를 우선 재활용한다. 원작 클리어 포즈 WAN17/Pose를 사용한다.
- 던전은 시작방·이동방·계단방의 2~3개 방과 통로로 단순화한다. B-1까지는 전투 없이 등장 포켓몬을 우호적으로 처리한다. 간단한 자동 전투는 선택 단계 B-2로 남기며, 착수 전에 사용자와 추가 여부·범위를 확정한다. 원작 출현 종류·상대 분포와 새 배치 수·생활 정책을 분리한다.
- 추출·변환은 오프라인 Python/SkyTemple 도구, 실행은 C++17/Win32/WIC/작은 PBGRA DIB/UpdateLayeredWindow를 기본으로 한다. Python·GTK·에뮬레이터·원작 VM·LLM을 런타임에 상주시킬 필요는 없다.
- 기본 UI 스레드 1개와 사건·deadline 기반 갱신으로 시작한다. 같은 프레임 재제출, 매 프레임 PNG 디코드·BFS, busy loop를 피한다. 추가 스레드나 렌더러 변경은 실측 병목이 있을 때 판단한다.
- 논리 타일, 장면 픽셀, 카메라/DIB, Windows 화면 좌표를 분리한다. 장면은 고정한 창 내부에 표시하고 표시 영역과 교차하는 요소만 합성한다. 사용자 요청으로 카메라 컷·조작은 제외한다. 탐험 이동으로 데스크톱 창을 이동시키지 않는다.
- 원본 ROM은 읽기 전용이다. 2026-10-13 사용자 최신 지시로 원본 ROM과 전체 추출 입력 및 검증 패키지를 `assets/original/`에 커밋해 세션 간 공유한다. 이전 게임 자산 커밋 제외 지침은 이 명시된 입력에 대해 변경됐다. 인증 정보는 커밋하지 않는다. 출처·변환 버전·크레딧을 보존하고 실행 설치물에는 필요한 선택 자산만 포함한다.
- 설정값·내부 클래스·빌드 구성은 Codex가 결정한다. 의존성 추가나 임의의 대체 자산으로 검증 실패를 감추지 않는다.

B·C의 세부 구현 명세는 해당 단계 진입 시 실제 A 산출물과 실패 기록을 기준으로 확정한다. A에서 이후 단계의 전체 상태 머신이나 전체 이벤트 VM을 미리 구현하지 않는다. 저장 형식은 버전을 두어 B의 탐험 상태와 C의 생활 상태를 확장할 수 있게 한다.

**의존성:** A-1 자산 준비와 A-2 렌더러 준비는 독립 개발 가능하다. A-3은 양쪽 결과가 필요하다. A 완료 뒤 B-1로 진행한다. B-1 완료 시 사용자와 B-2 추가 여부를 확정한다. 추가하면 B-2 검증 후 C, 제외·보류하면 비전투 계획으로 C에 진입한다. 자원이 없으면 가능한 독립 작업을 계속하되, 미완료 gate를 완료 처리하거나 다음 단계를 완료했다고 보고하지 않는다.

**2026-10-13 최신 사용자 지시:** origin/work 기준 `19ea3a1`의 기존 A 구현·원본 ROM·ZIP catalogue를 재사용해 B-1 지도·BFS·아이템/친구/계단 목표·onceKey·저장/복원부터 진행한다. 원작 타일 변환은 B-1에서 수행한다. A-3 잔여 검증은 pending으로 유지하며 A 재작성·파일 재업로드 요청을 선행하지 않는다. 실제 B-1 사용법·현재 제한은 [B1_USAGE.md](B1_USAGE.md)를 따른다.

## 4. A 단계의 입력·산출물 계약

### 4.1 입력과 준비

- 고정 커밋은 SOURCE_RESEARCH.md를 사용한다. 새 버전으로 바꾸기 전에 실제 API·출력 호환성을 확인하고 변경 이유를 기록한다.
- Python 가상환경과 필요한 직접·전이 의존성을 준비해 import smoke test부터 수행한다. 재현 가능한 버전·설치 절차를 남긴다. SkyTemple GUI의 확률 계산만 필요할 때 GTK 초기화를 따라 가져오지 않는다.
- Windows는 MSVC/Windows SDK의 Release 빌드와 실제 실행 환경을 확보한다. Linux에서의 문법 검사·크로스 빌드만으로 Windows 실행을 통과 처리하지 않는다.
- ROM 경로는 사용자의 로컬 입력이다. 식별 결과로 지원 여부를 판정하고, 하늘의 탐험대와 어둠·시간의 탐험대 구조를 동일하다고 가정하지 않는다. 판본별 주소·언어·설정을 사용한다.

ROM이 없으면 공개/합성 fixture로 변환 규칙·파일 검증·렌더러를 준비한다. 지원되지 않는 ROM이면 판본과 실패 위치를 기록한다. Windows가 없으면 플랫폼 독립 로직과 빌드 절차를 준비한다. 사용자에게 필요한 요청은 ROM 제공과 실제 Windows 실행 접근으로 한 번에 묶고, 그동안 독립 작업을 진행한다.

### 4.3 인터페이스와 호환성

필드 의미는 ASSET_MAPPING.md, 최소 타입은 IMPLEMENTATION_HANDOFF.md §3을 따른다. A에서 확정할 연결은 다음으로 제한한다.

- Extractor/Packer는 schemaVersion·assetVersion·출처를 포함한 catalogue와 선택 asset manifest를 만든다. AssetStore는 assetKey로 조회하고 Animator는 animationId·direction·mode·시간을 입력받아 frame/marker/finished/nextDeadline을 반환한다.
- Renderer는 현재 frame과 레이어, cameraOriginScenePx·viewportSizePx·integerScale을 받아 작은 PBGRA surface를 합성한다. 카메라 이동은 논리 위치·경로·RNG를 변경하지 않는다.
- 파일의 byte size·count·offset·rect·버전을 로드 전에 검사한다. 음수·범위 밖 값, 깨진 참조, alias 순환을 명시적으로 거부한다. 알 수 없는 판본·필수 schema는 임의로 해석하지 않는다.
- 선택 패키지는 참조한 atlas와 메타데이터가 닫힌 집합이어야 한다. 호환성 검증용 fixture 하나를 추출·변환·런타임 양쪽에서 공유하고 생산자·소비자의 해석이 같은지 검사한다.

JSON·compact binary 등 형식은 실측 크기와 구현 비용으로 결정한다. 오프라인 감사용 JSON이 있다는 이유로 런타임에 큰 JSON 의존성을 추가하거나 이중 schema를 만들지 않는다. 확정한 형식·읽기 예제를 실제 구현과 함께 기록한다.

## 5. A-1 — 원작 데이터·자산 준비

### 작업 순서

1. ROM hash/edition/language와 도구 커밋을 기록한다. 읽기 전후 ROM 해시를 대조한다.
2. S01~S07 경로로 던전 정의·MAPPA·MD·item·필요 문자열을 연결한다. 정상 일반 층과 start_after가 0이 아닌 던전의 첫층·끝층을 검증 집합에 넣는다. 전체 정의를 다룰 파이프라인을 만들되 최초 실행·자산 변환은 작은 선택 집합부터 검증한다.
3. localFloor는 0 기반, groupFloor=start_after+localFloor로 배열을 조회한다. GUI의 그룹 기준 floor_id에는 start_after를 다시 더하지 않는다. 도장 ID는 원본 특례로 분리하고 미검증·미지원 상태를 기록한다.
4. normal/MH와 아이템 context를 분리한다. CDF는 직전 비영 누적값의 차분으로 정수 가중치를 구하고, 아이템은 category별 조건부 분포를 유지한다. guaranteed는 별도 목록으로 남긴다. 빈 분포와 잘못된 비단조 값은 구분한다.
5. 대표 1~2종을 실제 MD→signed spriteIndex로 선택한다. MONSTER/monster.bin 및 m_attack.bin은 해당 압축 경로로, m_ground.bin은 raw WAN으로 읽는다. CharaWanHandler.deserialize→merge_wan→export_sheets를 사용한다. 종·폼·성별을 도감 번호로 뭉개지 않는다.
6. 원본 시트를 공통 atlas/manifest로 변환한다. alias/CopyOf·방향별 프레임·duration·anchor·그림자·marker를 보존한다. crop 원점을 모든 좌표에 동일하게 적용하고 재조립한 프레임을 변환 전 RGBA와 대조한다.
7. Walk, Idle, Eat, Sleep, Wake, Pose를 출력하고 필요한 경우 EventSleep/Laying도 보존한다. 1행 Eat/Sleep을 8방향으로 조작하거나 없는 PNG를 alias 누락으로 오판하지 않는다. 대표 검증 개체는 필수 동작을 실제 지원하는 것으로 선정하며 다른 개체의 누락은 support report에 남긴다.
8. tick 값·원본 속도/반복 플래그와 잠정 tickHz를 별도로 보존한다. 공개 GIF의 duration×20ms를 원작 시간 기준으로 쓰지 않는다. 선택 결과를 검사한 뒤 패키지를 확정한다.

### 완료 조건

대표 집합에서 실제 ROM 추출과 WAN 병합·시트 변환이 성공하고, catalogue·manifest 참조와 필수 동작 지원이 검사돼야 한다. 재실행 결과가 일치하고 errors/support 보고서가 존재해야 한다. 공개 자산이나 가짜 ROM ID만 있으면 A-1의 원작 검증은 pending이다.

A의 대표 샘플 통과는 G1의 전체 ROM 순회·G2의 전체 종/폼 지원 통과가 아니다. 전체 목록의 추출·감사 경로를 확장 가능하게 만들고 미실행 범위를 남긴다. 대표 종을 특정 두 종으로 고정하거나 종별 수작업 시트 편집을 사용자에게 요구하지 않는다.

## 6. A-2 — Windows 창·재생·계측

### 작업 순서

1. 최소 빌드와 실행 경로를 만든다. WIC S22의 decode/format conversion/DIB 흐름만 가져오고 파일 선택 UI·불투명 샘플 렌더러는 제거한다.
2. WIC를 PBGRA로 변환해 캐시하고 작은 top-down DIB에 합성한다. premultiply를 두 번 적용하지 않는다. 소스·목적 사각형 clipping과 stride/byte size의 overflow 검사를 포함한다.
3. 200×200 실제px 고정 layered 창, 정수 확대·nearest 샘플링, 항상 위 토글·드래그·focus 방해 최소화를 구현한다. 크기 단위와 DPI 적용 규칙은 구현 시 명시하고 다른 모니터에서 화면 밖 위치를 제한한다.
4. animation ID와 방향·loop/finite 모드를 선택해 볼 수 있는 최소 검증 모드를 제공한다. loop clip은 외부 종료 조건으로 끝내고 finite clip의 finished/marker는 경과 경계를 기준으로 중복 없이 내보낸다.
5. monotonic clock으로 tick 경계를 처리하고 다음 변경 시점만 예약한다. 프레임 지연·일시 정지·복귀 후 과거 프레임을 폭주 재생하지 않는다. A의 검증 모드에서 Sleep은 명시적 종료로 중단하고 C의 생활 deadline과 혼동하지 않는다.
6. 작은 테스트 배경으로 표시 영역·경계 clipping을 자동 검증한다. 사용자 카메라 조작은 구현하지 않는다. A에서 완성 던전 생성기·타일 엔진은 구현하지 않는다.
7. 최소 hide/lock/display/power 렌더 중단·복귀를 준비하고 CPU 시간, working set/private bytes/peak, 렌더 제출 수와 디코드 횟수를 계측한다. 프로그램별 활동 분류와 전체 생활 전환은 C에서 구현한다.
8. 자원 오류 시 HRESULT/OS 오류와 assetKey를 기록하고 기존 정상 상태를 보존한다. COM/GDI/window/timer의 정상·오류 경로 해제를 검사한다. 기본 종료·창 위치 복원은 작은 버전 저장으로 처리한다.

### 완료 조건

시험 패키지로 창·투명도·동작 재생·경계·타이머를 검증하고 실제 Release Windows 실행 결과를 남긴다. WIC decode는 최초 로드/캐시 miss에만 발생하고 동일 frame의 불필요한 surface 제출은 없어야 한다. 공개/fixture 재생 통과는 A-2의 렌더러 결과이며 A-3의 원작 통합 결과로 바꾸어 보고하지 않는다.

A는 필수 동작을 검증 모드로 재생하는 단계다. 자율 탐험, 실제 음식 소비, 자동 생활 주기, 활동 분류를 완성했다고 보고하지 않는다. 원작 부가 효과·계단 그림 매핑의 미해결이 A의 몸체 애니메이션 검증을 막지는 않는다.

## 8. B·C 진입 시 확정할 사항

### B-1 — 비전투 탐험

원작 tileset/DMA 연결과 출현 catalogue를 실제 A 패키지 계약으로 확장한다. 원작 파서의 타일·청크 변환은 오프라인에 두고 생성 시 필요한 autotile 선택 규칙만 네이티브에서 사용할 수 있도록 정리한다. 매 층 Python을 실행하거나 모든 층 전체 PNG를 저장하는 구조를 기본으로 채택하지 않는다.

2~3개 방과 통로, 도달 가능한 출발·계단, FIFO BFS·목표 캐시·유한 복구를 구현한다. 가용 타일 비복원 배치와 요청 수/예산/공간 제한, guaranteed 초과의 미배치 사유를 명시한다. 전체 점유·후보 0·과다 요청에서도 종료하며 원본 가중치를 변경하지 않는다.

현재 층의 아이템·친구·미탐색 영역·계단을 목표로 자동 진행하고 마지막 층에서 원작 Pose 뒤 귀가한다. instanceId/onceKey와 versioned snapshot으로 획득·층 이동·클리어 중복을 막는다. 수집·클리어 중 강제 종료 및 복원, 막힌 친구/아이템, RNG 복원을 검사한다.

native 지도 10,000개 시드, 출현 가중치 통계, 유한 배치·복구, 여러 층·던전 연속 탐험을 통과해야 B-1 완료다. 기존 [geometry 검사](research/checks/geometry_check.py)의 Python 결과는 native 결과를 대신하지 않는다. 계단 논리·임시 검증 표시와 원작 계단 그림 지원은 구분하고, 미확인 그림은 unresolved로 기록한다.

### B-2 — 선택 자동 전투: 착수 전 확정

**2026-10-13 최신 사용자 확정:** 탐험 종료 생활 루프를 먼저 연결한 뒤 기본공격355 하나의 최소 전투를 구현하도록 승인했다. [B1_GAMEPLAY_TASK.md](B1_GAMEPLAY_TASK.md)와 [06_B2_COMBAT_IDS.md](research/06_B2_COMBAT_IDS.md)가 이번 범위·12개 검증 기준이다. 아래의 미확정·승인 대기 문구는 과거 검토 기록이며 이번 확정 범위에 다시 적용하지 않는다. 기술·레벨·가방·적HP표시·승리 자동귀가는 계속 제외한다. 실제 코드·실행 결과는 PROJECT_STATE.md를 따른다.

B-1이 실제로 움직이는 상태에서 짧은 자동 전투가 펫의 재미와 화면 가독성에 도움이 되는지 검토한다. **B-1 완료 시 사용자에게 추가·제외·보류 여부를 확인하고, 전투 구현에 들어가기 전에 범위·규칙·완료 조건·검증 방법을 확정한다.** 지금 전투 구현을 승인한 것으로 해석하지 않는다. 미확정이면 B-2는 미착수로 남기고 관련 없는 독립 작업만 진행한다.

최소 후보는 접촉 시 자동 전투, 기본 공격 하나, 원작 공격·피격 동작과 필요한 능력치·계산 재활용, 패배 시 귀가다. 이는 검토안이며 다중 기술·상태이상·복잡한 AI를 포함한 확정 명세가 아니다. 조우 대상의 관계 정책, 공격·턴/타이밍·피해와 승패 처리, 보상·패배 처리, 전투 중 종료·복원, 성능 예산을 착수 전에 정한다. 원작 계산을 단순화한다면 차이를 기록한다.

A/B-1에서 준비할 확장 여지는 작게 유지한다. 포켓몬 관계와 조우 후 행동은 하나의 정책 경계에 두고 기본값은 우호·인사로 한다. 모든 개체가 영원히 우호적이라는 가정을 여러 모듈에 흩어놓지 않는다. 공격·피격 자산은 원본 참조와 지원 여부를 보존하되 선택 패키지에 미리 추가하거나 전투용 HP·AI·화면을 선행 구현하지 않는다. 기존 versioned snapshot을 확장할 수 있도록 유지하며, 전투 상태 필드는 B-2 확정 후 정의한다.

전투를 추가하기로 확정하면 관련 연구 문서의 비전투·우호 정책, 데이터 계약·자산 선택·저장 상태·B/C 검증 기준을 함께 갱신한다. 제외·보류하면 B-1 결과와 기존 C 계획을 유지한다.

### C — 생활·활동과 최종 지원

SSB/SSA의 필요한 식사·수면·기상 장면만 유한 cue로 변환한다. 원작 Sleep/Wake/Eat와 소품·효과를 연결하고 음식 소비 once, 수면 deadline, 절전 후 생활 상태 복구를 완성한다. 친구 인사 등 신규 cue와 원작 동작을 구분한다.

foreground/idle/lock/display/power만 관찰해 활동 상태를 분류한다. 키 입력 내용·스크린샷·브라우저 이력을 수집하지 않는다. 감지 실패 시 Unknown으로 처리해 펫의 독립 생활이 유지되게 한다. 절전 중 실시간 연산과 복귀 시 누적 프레임 재생은 하지 않는다.

지원 판본의 전체 정의·층·종/폼 목록을 자동 순회하고, 원본 수·참조·지원·미지원 목록을 보고한다. 일부 종의 동작 누락은 명시된 기능 축소로 처리한다. 필수 대표 개체조차 필수 동작을 못 재생하는 상태를 완료로 판정하지 않는다.

전체 데이터 지원 범위와 기본 설치에 포함한 선택 자산 범위를 별도로 보고한다. 20MB 목표를 맞추려고 누락된 개체를 전체 지원으로 표시하지 않는다. 모든 자산을 동시 메모리에 올리지 않고 선택 로드·캐시를 사용한다. 추가 자산 패키지 정책은 실제 용량과 지원 감사 결과로 결정하고 총 설치·다운로드 크기를 따로 기록한다.

생활·탐험 반복, 소비/획득/클리어 중 종료·복원, 실제 OS 사건, 24시간 안정성 검사 및 최종 성능을 통과해야 C 완료다. 최종 부가 효과·계단 그림은 실제 매핑된 자산만 지원으로 표시하고 미해결 범위가 있으면 최종 보고에 남긴다.

## 9. 성능·검증 기록과 자율 진행

### 성능 판정

잠정 목표는 일반 실행 평균 CPU 1% 이하, RAM 30,000,000bytes 이하, 기본 선택 설치물 20,000,000bytes 이하이다. 최초에는 수치보다 기준선을 확보하고, 최종 C에서는 고정된 동일 조건으로 판정한다.

- CPU는 GetProcessTimes의 실제 kernel+user 시간과 wall time으로 한 코어 기준 %를 구하고, 전체 논리 코어 정규화 %도 함께 보고한다. 최종 CPU 1% 판정은 보수적으로 한 코어 기준을 사용한다. 코어 수로 나누어 실패를 숨기지 않는다.
- RAM은 working set와 private bytes의 정상 시나리오 최대값을 각각 30,000,000bytes와 비교한다. 최초 decode·캐시 miss의 transient peak는 별도 기록하고 스파이크·지속 증가 원인을 확인한다.
- 설치 크기는 exe·배포 DLL·선택 데이터/자산·credits/licenses 전체 합계다. 추가 다운로드와 개발 도구·ROM은 별도로 보고한다.
- C의 15분 시나리오는 런타임 보고서 §7을 따른다. 평균/P95/최대, 샘플 간격·코어 수·DPI·OS·Release 옵션·자산 수/bytes를 기록한다. A에서는 탐험·완성 생활 기능의 성능을 추정하지 않는다.

### 작업 종료와 재개

각 세부 작업마다 구현·검사·수정까지 진행하고, 통과한 gate와 pending 항목을 분리한다. 실패 시 원인과 최소 수정안을 판단해 관련 검사만 다시 수행한다. 내부 클래스 수·가상의 코드 구조를 늘리거나 사전 최적화로 범위를 확장하지 않는다.

PROJECT_STATE.md에는 현재 구현·실행된 검사·막힌 자원·다음 실제 명령 또는 함수 위치만 남긴다. 설계 변경은 DECISIONS.md, 수행 증거는 날짜·주제별 docs/logs/에 기록한다. 원래 조사 ZIP와 checks/package_validation.json은 수정 전 기록으로 보존하고 새 테스트 결과는 별도 기록한다.

사용자에게는 단계 시작 시 범위·예상 시간을 알리고, 크게 초과하거나 새 문제로 범위가 늘면 이유·추가 시간·기대 효과를 설명한다. ROM·Windows 접근이나 중요한 제품 요구사항 변경이 필요할 때만 묻는다. 일반적인 코드 구조·설정값·검사·오류 수정은 자율 수행한다.

변경을 검증하고 커밋한 뒤 허용된 작업 브랜치로 실제 git push한다. 원격 브랜치 SHA와 로컬 커밋 일치를 확인하고, 실패하면 미반영 커밋·원인을 기록한다. 작업 완료와 인증·원격 반영 성공을 별도로 판정한다.
