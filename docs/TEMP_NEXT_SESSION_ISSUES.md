## 확인된 사용자 체감 문제

1. 캐릭터가 목적지를 향하지 않고 무작위 이동을 반복한다.
2. 계단이 눈앞에 있어도 계단으로 이동하지 않는다.
3. 목적지 도착이나 인카운터 접촉 외에도 계속 이동한다.
4. 3층 클리어 후 Pose 재생과 귀가 재현은 확인됐으나, 귀가 과정이 불필요하게 길다.
5. 귀가 중 배경이 투명해져 목적지와 진행 상태를 알 수 없다.
6. 현재 테스트에서는 귀가 단계가 끝나지 않고 캐릭터가 계속 왼쪽으로 걸어간다.
7. 직선 이동 자체는 끊기지 않지만, 방향 전환 시 한 번 멈추거나 머뭇거린 뒤 이동해 어색하다.
8. 친구 인카운터는 같은 칸에 겹치기보다 한 칸 옆에서 서로 바라보며 상호작용하는 편이 자연스럽다.
9. 던전 외곽에 여유 프레임이 부족해 캐릭터가 바깥 벽에 가까이 가면 화면 가장자리에 빈 투명 영역이 보인다. 창이 축소된 것처럼 보이고 던전 가시성이 떨어진다.
10. 직선 이동이 끊겨 보이는 현상은 캐릭터가 아니라 배경 이동/카메라 렌더링 문제다.

## 현재까지의 판단

귀가 상태로 전환된 뒤에도 탐험용 이동 로직이 활성화되어 있는 상태로 추정한다. 특히 다음 가능성을 우선 점검한다.

- `ReturnHome` 전환 시 `Explorer`/`Navigator`가 정지하지 않음
- 기존 계단·frontier 목표 또는 이전 경로가 귀가 상태에서도 유지됨
- 귀가 목적지의 도착 판정 또는 귀가 완료 이벤트가 발생하지 않음
- 경로 실패 시 재계획이 무한 반복됨
- 귀가 중 배경/집 목적지 표시가 없어 진행 상태를 확인할 수 없음
- `fade-out → 집 씬 전환` 이벤트가 연결되지 않음
- 귀가 완료 후 `Eat`/`Sleep`으로 이어지는 상태 전환이 누락됨
- 방향 전환 전에 불필요한 판단·대기 시간이 들어가 방향 전환 후 첫 이동이 늦어짐
- 배경 스크롤 또는 카메라 갱신이 이동 중 연속적으로 처리되지 않아 직선 이동이 끊겨 보임
- 던전 외곽 벽과 카메라 표시 영역 사이의 padding이 없어 맵 바깥이 투명하게 노출됨

## 목표 동작

```text
3층 계단 도착
  → Pose17 유한 재생
  → 탐험 이동 즉시 중지
  → 0.5~1초 fade-out
  → 월드 이동 없이 집 씬으로 전환
  → 0.5~1초 fade-in
  → Eat
  → Sleep
```

귀가 중 필드에서 실제로 걸어가는 연출은 사용하지 않는다. 귀가 시간은 이동 경로에 따라 길어지면 안 되며, Pose 종료부터 집 장면 표시까지 약 1~2초를 목표로 한다.

## 수정·검증 순서

1. `ReturnHome` 진입 시 탐험 이동, 경로 재계획, 기존 목표 갱신을 차단한다.
2. 귀가 전환을 물리적 이동이 아닌 장면 전환 이벤트로 분리한다.
3. `ReturnHome` 이벤트가 한 번만 실행되도록 `onceKey` 또는 동등한 중복 방지 장치를 둔다.
4. fade-out 완료 후 집 씬을 교체하고 fade-in한다.
5. 집 씬 표시 후 `Eat → Sleep` 전환을 확인한다.
6. 다음 시나리오를 측정한다.
   - 계단이 바로 앞에 있을 때 계단으로 이동하는가
   - 목표가 없을 때 무작위 이동하지 않는가
   - 3층 클리어 후 더 이상 필드에서 걷지 않는가
   - 귀가 전환이 1~2초 안에 끝나는가
   - 귀가 후 식사와 취침으로 이어지는가
   - 이벤트가 반복 실행되거나 귀가 상태에 고착되지 않는가

추가 이동 연출 기준:

- 캐릭터는 타일 단위로 순간이동하지 않고 연속 보간되어야 한다.
- 방향 전환 시 판단을 반복하지 말고 가능한 즉시 방향을 바꿔 이동한다.
- 목적지와 무관한 불필요한 방향 전환·우회 이동을 줄인다.
- 배경은 캐릭터의 이동 중 끊김 없이 부드럽게 스크롤되어야 한다.
- 친구와의 상호작용은 같은 칸 중첩 대신 인접 칸 정지·방향 전환 후 실행한다.

추가 화면 여백 기준:

- 던전 맵 바깥에 최소 1~2타일 이상의 외곽 벽/padding을 둔다.
- 카메라가 외곽 벽을 표시할 때도 표시 영역 전체가 던전 배경으로 채워져야 한다.
- 캐릭터가 외곽 벽에 붙어도 바깥쪽에 투명한 빈 프레임이 노출되지 않아야 한다.
- 논리 맵 경계, 카메라 clamp, 렌더 viewport clipping을 분리해 검증한다.

## 검증 시 기록할 로그

최소한 다음 상태 전환을 시간과 함께 기록한다.

```text
Explore
→ Pose
→ ReturnHome
→ FadeOut
→ Home
→ FadeIn
→ Eat
→ Sleep
→ Wake
→ Ready/Idle
→ 다음날 Explore
```

`ReturnHome` 진입 이후 `Navigator.plan` 또는 이동 tick이 호출되면 실패로 기록한다. 최신 사용자 기준은 ReturnHome이1~2초 안에 끝나고 Eat/Sleep/Wake/다음날 Explore로 이어져야 한다. 예전5초 한도 대신1500ms 구현·2초 실행 gate를 적용한다.
