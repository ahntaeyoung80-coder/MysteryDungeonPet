새 사건 배우도 기존 유한 population 예산 안에서 배치한다. 개체 ID 범위 검사와 `enemyInstance`, `ActorFinished`, 행동 큐가 기대하는 범위를 함께 검토한다. 세 번째 배우를 기존 companion 슬롯에 덮어쓰지 않는다. 신규 상태 검증 없이 기존 enum의 최대값만 늘리는 변경은 피한다.

편집 원본은 JSON으로 두고 오프라인 도구가 참조·감정·조건을 검증한 작은 실행 catalogue로 변환한다. 실행 쪽은 기존 Reader/Writer·패키지 방식을 재사용하는 방향으로 검토하며 범용 JSON 라이브러리/스크립트 VM을 새로 상주시킬 필요는 없다. 문서 JSON의 자유 서술 conditions를 코드에서 자연어 해석하지 않고, 지원하는 조건 코드와 필수 매개변수로 변환한다. 초안·검증·실행 등록 상태를 분리해 승인/검증 전 문장이 자동 배포되지 않게 한다.

### 진행과 우선순위

한 번에 주요 사건은 하나다. 기본 흐름은 **후보 필터→선택/배치 고정→접근→대화→필요 행동→실제 결과 확정→결과 대화→해산/목표 복귀**다. E05처럼 필요한 단계만 사용하고 임의 스크립트 언어로 일반화하지 않는다.

이미 시작된 공격/피격과 피해 확정 경계를 먼저 마친다. 기절·강제 귀가·생존 회복·필수 층 전환은 평상시 수다보다 우선한다. 새 사건은 안전한 경계에서만 시작한다. 대화 중 이동/전투 AI가 임의 행동하지 않게 명시적으로 중단하고, 재개할 때 사용하지 않은 행동권을 추가 지급하지 않는다. 안전을 위해 취소하면 예약만 해제하며 이미 확정된 지급/차감은 되돌리지 않는다.

사건은 기존 탐험 목표를 잠시 보관하되 복귀 시 위치/점유가 달라졌으면 재탐색한다. stale 경로를 그대로 실행하지 않는다. 중단 뒤 오래된 동작 완료 통지는 run/floor/actor/action 키로 무시한다.

### RNG와 저장

기존 지도·출현·전투 RNG를 새 대사 선택으로 소비하지 않는다. 이벤트·대사·하루 일정에 각각 고정 규칙으로 파생한 별도 RNG 상태를 두고 저장한다. 표준 라이브러리 구현마다 달라질 수 있는 임의 문자열 hash로 seed를 만들지 않는다. 후보 필터와 시점이 확정됐을 때만 추첨하고 렌더/매 프레임에는 추첨하지 않는다.

다음 MDES 버전(현재 기준 제안은12)에 대화 세션·사건 상태·별도 RNG·최근 선택/쿨다운·예약/결과·일정을 보존한다. 기존 MDES1~11은 새 필드가 비어 있는 상태로 읽으며 이미 받은 아이템을 다시 주지 않는다. 기존 MDPE1은 읽을 수 있게 유지하고 MH/shop/trap 자료 추가는 명시 버전 확장 또는 별도 버전 catalogue 중 변경 범위가 작은 쪽을 택한다. 두 형식의 버전을 혼동하지 않는다.

**복원 정책 제안:** 명시 `--explore`는 사건·대사·예약·임시 배우까지 상세 재개한다. 일반 실행은 기존처럼 길드 아침에서 시작하되 같은 날의 일정/목적지와 확정 결과는 유지한다. 중단된 던전 사건의 미소비 예약·임시 배우는 해제하고 포기 상태를 저장한다. 이미 차감한 물건/보상을 되돌리거나 같은 결과를 다시 지급하지 않는다. 휴일은 같은 목적지 방문을 다시 시작할 수 있어도 횟수/식사/날짜는 중복 적용하지 않는다. 일정은 기존 `startGuildMorning`/다음 Explorer 생성 과정에서 누락되지 않도록 명시 인계한다.

저장 성공 전/후 종료, 잘린 저장, 구형 저장, catalogue 변경, 알 수 없는 새 ID에서 결과가 어떻게 되는지 정의한다. 유효하지 않은 대화는 안전하게 종료하고 이미 확정된 거래 결과는 유지한다. 임의 다른 사건/문장으로 교체해 “정상 복원”으로 표시하지 않는다.

## 5. P1·P2 — 실제 캐릭터와 상황 대사

### 배우 자산

기본 던전15의 실제 출현 집합부터 패키지화하고 이후 허용 맵의 MD 합집합으로 늘린다. normal/MH/고정 길드원/상점 역할을 따로 추적한다. 기존 `prepare_party_actor.py`, `prepare_starter_characters.py`, `prepare_dialogue_portraits.py`의 추출/원본 대조를 재사용한다. 같은 sprite를 공유하는 MD는 그림을 중복 생성하지 않되 논리 정체성·폼 매핑은 보존한다.

필수 동작은 Walk0/Attack1/Hurt6/Idle7이다. Nod22/Faint33 결손은 원작 조사표에 따라 처리한다. Nod가 없는 배우는 이미 정한 유한 Idle 응답을 쓰고 다른 동작을 이름만 바꿔 복제하지 않는다. 필수 몸체 자산이 없는 종을 켈리몬으로 대신 표시하지 않는다. 선택 맵의 전체 출현 후보를 처리한 뒤 맵을 활성화하거나, 미지원과 원작 분포 변경을 명시한 별도 제품 정책으로 남긴다.

NPC 자산은 현재 층/방문 장면의 필요한 종만 로드·공유하고 프레임마다 PNG를 해독하지 않는다. 단순 유한 캐시부터 적용하고 실제 사용량을 측정한다. 521종 전체 atlas를 한꺼번에 상주시킬 계획은 없다.

### 대화 세션

화자 역할과 실제 instance를 매 문장 해석한다. 주인공·동료는 현재 선택 캐릭터를 쓰며 NPC는 사건 소유의 실제 개체를 쓴다. 렌더에 넘기는 결과는 문장·실제 화자·요청 감정·실제 감정·읽기 시간이다. 순차 출력 완료 후 읽기 시간을 주고 필요한 경우 페이지를 나눈다. 원작 테두리/초상화 위치·200×200 화면을 유지하며 긴 문장의 한글 줄바꿈을 확인한다.

**화자 초상화 하나만**, 명찰 없음. 감정은 문장 데이터에서 지정한다. 결손이면 같은 배우 Normal0, Normal도 검증되지 않으면 그 배우의 우호 대화/사건 배역을 후보에서 제외한다. 이것을 원작 적 출현표에서 해당 종을 삭제하는 것으로 확대하지 않는다. 시스템 안내에는 초상화가 없다. 원작 talk group 숫자를 한국어 성격으로 임의 번역하지 않고, 새 말투 태그 neutral/lively/careful/warm과 별개로 보존한다. 초기 기본 말투 제안은 neutral이다.

대화의 focus pair를 정해 화자와 상대가 서로 본다. 3인 문답이면 발화 대상 둘을 서로 보게 하고 나머지 청자는 화자를 향한다. 대사마다 턱없이 회전하거나 걸음 clip에 이전 방향이 남지 않게 표시 방향과 동작 방향을 함께 갱신한다. 시스템/무언 감상 구간은 이 문답 규칙과 분리한다.

먼저 기존 companion.checkin, npc.greet, sleep.greet, wake.alarm, morning.depart, defeat.player/partner의 고정 발화를 문답 데이터로 이관한다. 다음으로 실제 회복/획득/층 도착/전투 승리/완료 사실이 있는 상황만 확장한다. “위기” 문구가 안전한 산책에서 나오거나, 회복 안내를 임의 화자의 말로 바꾸지 않게 한다. 필수 문구 **`탐험을 성공적으로 마쳤다`**는 유지한다.

상황/생존/환경/재고/역할 조건을 통과한 묶음 중 가중 선택하고 최근 묶음은 피한다. 대안이 하나면 무한 재추첨 없이 그 하나를 쓰며 후보가 없으면 발화를 생략한다. 문장별로 무작위로 섞지 않는다. 사건의 문답 변형 계열은 유지한다. 시작할 때 미래 성공을 확정하지 않고, 결과 분기는 실제 사실이 확정됐을 때 같은 변형 계열 안에서 한 번 선택·저장한다. 사건이 없는 일반 상황도 동일한 선택 경로를 사용한다.

캐릭터 교체는 대화·공격·사건의 결과 확정·입수/퇴장 중 보류하고 안전한 단계 경계에서 몸체/얼굴을 함께 적용한다. 프로필의 종 중복 금지는 그대로 유지한다. 검증에는 나옹·먹고자와 성별 슬롯, 플레이어/동료 역할 반전을 포함한다.

## 6. P3~P6 — 9개 탐험 이벤트와 맵·아이템 다양성

### 첫 연결과 맵 확장

E05는 안전한 곳의 무언 감상→서로 보기→짧은 문답으로, E09는 방문용 Walk를 갖춘 실제 비버니/가재군 등장→인사→해산으로 먼저 검증한다. E01은 격려부터 연결하고 재고/예약이 준비된 뒤 나눔을 추가한다. 이 세 사건으로 공통 진행기를 실제 실행해 보고 나머지 조건을 확장한다.

[map-eligibility.json](../research/2026-10-21-event-resources/map-eligibility.json)의 기본 던전15는 1~7F 모두 상점/MH/워프 조건0이다. **기본 맵에 세 사건을 강제로 넣는 것을 기본값으로 삼지 않는다.** 초기에 던전15는 유지하고, 원작 조건·타일·출현 자산·최종 목적지가 검증된 새 맵을 하나 추가한 뒤 넓힌다.

현재 자료에서 세 필드가 동시에 양수인 검토 후보는 던전17 Amp Plains(10층, 1~10F), 던전24 Crystal Cave(11층, 3~11F)다. 이는 자료 필터 결과이며 실행 가능/최종 선정 완료가 아니다. 원작 명칭은 정적 설정 출처다. 고정/스토리 층·후속 구역·종결 ground를 확인해 비용과 동작 범위가 작은 후보를 먼저 선택한다. ID가 연속이라는 이유만으로 다음 던전이 종료 장소라고 판단하지 않는다.

허용 맵 데이터에는 던전/구역 ID·유효 층·실행 패키지·환경 태그·normal/MH·item contexts·상점/함정 조건·종결 목적지/입장·퇴장 지점을 묶는다. 해당 맵의 마지막 층 후 정확한 종료 장소 방문→필수 성공 안내→귀가를 확인해야 자동 맵 선택 풀에 넣는다. 다른 맵에도 Steam Cave Peak를 공통 종착지로 붙이지 않는다. 원작 최종 장소를 못 찾은 후보는 보류한다. 다음날 맵 선택도 하루 일정에 고정하고 실행 중 출현표만 바꿔 끼우지 않는다.

### 아이템과 결과 처리

아이템은 record ID를 기준으로 `표시/획득/사용/교환/사건 소유` 가능 여부를 나눈다. 공유 sprite/palette를 같은 물건으로 취급하지 않는다. 원작 normal·MH·shop·buried 등의 문맥을 섞지 않으며, 해당 층의 상대 비중을 원본과 대조한다. 추가 효과는 별도 검증한 것만 지원한다. 돈·상자 그림만으로 경제/개봉/상태이상 기능이 있는 것으로 표시하지 않는다.

재고는 소유자·item record·현재 수량·예약 수량을 관리하고 기존 열매 보유/소비와 중복된 원장을 만들지 않는다. 이행 시 현재 oran 수량을 신뢰하고 과거 획득 이력에서 소비한 열매를 복구하지 않는다. 반환용 물건은 일반 재고와 분리한다. 전달/거래는 조건 재검증→비용/수령/재고를 같은 결과로 적용→commitKey와 함께 저장→결과 문구 순서다. 실패하면 성공 대사를 출력하지 않는다.

## 7. P7 — E10 휴일: 마을부터, 온천까지

휴일은 **기상→하루 일정 고정→마을 또는 온천 방문→귀가→기존 식사6초→취침→다음날**이다. 던전 층 중간 쉼터나 던전178의 무작위 층 실행으로 만들지 않는다.

1. 일정 저장을 먼저 연결한다. 같은 날 재실행·절전 복귀로 탐험/휴일·목적지를 재추첨하지 않는다. 날짜 증가/식사 키는 runId만이 아니라 같은 하루 완료와 연결해 기존 루프를 한 번 실행한다. 지금의 startGuildMorning/Ready에서 새 Explorer를 만드는 경로를 함께 수정해야 한다.
2. 길목 P01P01A→마을 T01P01A/T01P02A의 검증된 통행 경로·주민 자리·정지 지점만 작은 장면 데이터로 만든다. 전체 SSA의 모든 이야기 배우를 복제하지 않는다. 고정 200×200 창 안의 기존 카메라 방식을 재사용하며 새 수동 카메라/컷 전환을 요구하지 않는다. 방문 중에는 층수 HUD가 없어야 하고 대화창/초상화를 포함한 최종 fade는 함께 적용한다.
3. 온천 P02P01A의 입수 전→입수→휴식→퇴장→코터스 인사를 추가한다. 스타팅 34 MD의 Float20을 실제 atlas로 추출/대조하고 입수 좌표·anchor·가림 마스크·물결625~629의 높이/방향/팔레트/시간을 확인한다. 1방향 Sit23/DeepBreath21을 8방향이라고 복제하지 않는다. 코터스352는 탕 가장자리에 둔다.
4. 대화 전에 서로 보게 하고 입욕 중 교체는 안전 경계까지 보류한다. 나옹·먹고자를 포함한 지원 조합을 점검한다. 휴일에 던전 보상/클리어 성공 문구를 발생시키지 않는다. 수치 회복·구매·보너스는 별도 정책이 없으면 붙이지 않는다.

원작 효과43 SteamClouds는 팔레트 미해결이며 온천 필수 호출 근거도 없다. 장식 후보로 두고 임의 색상/다른 효과로 원작 복원 완료를 주장하지 않는다. 반면 입수·몸체 가림·물결을 검증하지 못했다면 온천 전체 완료가 아니다. 그때는 “마을 휴일만 지원” 또는 “온천 주변 방문만 지원”이라고 구분한다.

초기 일정 정책 제안은 완료된 탐험일을 기준으로 일정 간격 뒤 하루 휴일을 주고 마을/온천 중 최근 목적지를 피하는 방식이다. 간격·확률·강제 휴일 여부는 아직 미정이며 OS 달력/사용자 활동 연동으로 범위를 넓히지 않는다.

## 8. 구현 시 검증·배포 계획

이번 문서 작성에서는 아래 제품 검사를 실행하지 않는다. 실제 코드/에셋 변경을 시작할 때 해당 단계의 검사만 먼저 선택한다.

| 변경 범위 | 우선 검증 | 실제 실행 확인 |
| --- | --- | --- |
|배우·초상화·선택 |기존 pet_character_scene_tests/pet_dialogue_portrait_tests와 Python 원작 대조 확장 |실제 종 몸체/얼굴, 감정 결손, 21종/역할 반전·성별·중복 금지 |
|문답/사건 기반 |새 데이터 참조 검사·후보 조건·RNG 비간섭·유한 단계·중단/재개 |한 화자/무명찰/서로 보기·긴 한글 문장·페이지·읽기 시간 |
|MDES/MDPE 확장 |기존 package_transition/exploration/revision 검사, 신규 버전/구형 이행/손상/중복 결과 회귀 |일반 시작·명시 복원·패키지 변경 후 실제 누적 재고/일정 |
|재고/교환/반환 |commit 직전/직후 종료, 동일 ID 재시도, 예약 경쟁·부족, 다른 주인 |표시 문구와 실제 차감/수령 일치 |
|맵/이동/전투 |completion/navigation_recovery/companion/survival 및 새 시나리오 |마지막층 방문/귀가, 임시 배우 막힘, MH·워프·공동 전투·기절 |
|휴일/연출 |일정/식사/날짜 once, 정지/재실행·시간 이동, 원작 효과/몸체 대조 |마을/온천 전체 생활, Float/물결/가림, 식사6초는 원속도 뒤1초 절단, 전체 UI fade |

강제 시나리오는 정상 흐름과 실패/취소/재실행을 재현할 수 있도록 도구에만 제공하며 제품 사용자에게 내부 단계/ID를 고르게 하지 않는다. 확률 검사는 고정 seed에서 후보 조건·상한·중복 억제를 대조한다. “무작위이므로 대충 맞음”이나 스크린샷만으로 저장/행동권을 통과 처리하지 않는다.

저장·공통 행동의 큰 변경인 P0/P5/P6에는 관련 검사가 통과한 뒤 한 번의 넓은 메모리/통합 검사가 필요하다. 같은 소스/자산에서 통과한 결과를 문서 후속 커밋마다 반복하지 않는다. 사용자에게 보이는 변경은 관련 검사→실제 EXE→소스/선택 자산/EXE 반영을 따르고 자동 전체 CI는 배포 후 백그라운드로 확인한다. CI 미완료/실제 Windows11 미확인은 별도 남긴다.

맵·배우 확대 후 선택 설치 크기, 로드/디코드 수, 이동/BFS·렌더 호출, working set/private bytes를 기존 기준과 비교한다. 장기/최종 성능 목표의 미검증을 이번 사건 단위 통과로 대체하지 않는다.

## 9. 첫 착수 범위와 남은 제품 결정

**다음 실제 작업으로 제안하는 범위는 P0**다. 기존 실행과 구형 저장을 고정한 상태에서 대사/사건/일정의 최소 데이터 계약·별도 RNG·버전 이행·취소/복원만 구현한다. 이어 P1의 기본 맵 배우 일치, P2의 기존 발화 이관, P3의 작은 사건 순서로 화면에 연결한다. 이 계획 작성 자체는 코드 수정 지시가 아니다.

| 결정할 정책 | 현재 제안/상태 | 영향을 받는 단계 |
| --- | --- | --- |
|새 맵 허용 범위 |던전15 유지+완료 장소까지 검증한 새 맵1개부터. 17/24는 검토 후보 |P4 |
|사건 빈도/최근 이력 |층당1/run당2 상한을 초기 제안. 가중치·쿨다운은 시나리오 검증 후 조정 |P3/P8 |
|열매 나눔 예비량·교환 |자동 회복 우선, 마지막 예비량 보호. 물품/비율 미확정 |P4/P6 |
|보상·분실물 미완료 |초기 무보상 제안, 사건 물품을 일반 소비로 전환하지 않음 |P5/P6 |
|휴일 주기·효과 |완료 탐험일 기반 주기 제안. 수치 보너스 미정 |P7 |
|일반 실행 복원 |길드 아침 유지+같은 날 일정/확정 결과 유지. 던전 임시 사건은 취소 제안 |P0/P7 |

위 사항은 구현 계획의 제안으로 표시하며 수치/정책을 몰래 확정한 것으로 취급하지 않는다. 원작 메시지 미해독은 작성 대사로 진행 가능하지만, 원작 대사로 표기하지 않는다. 워프 연출 ID는 E08 완성 전 추적하고 수증기43 팔레트는 장식 리소스의 별도 미해결로 남긴다. 실행 자산이 없는 종·종결 장소가 불명인 맵·결과 기능이 없는 성공 대사는 자동 후보에 넣지 않는 것이 전체 단계의 공통 완료 기준이다.
