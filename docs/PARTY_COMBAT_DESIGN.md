# 공동 전투 후속 설계·회귀 준비

2026-10-15 KST. [B 후속 계획](PARTY_AI_WORK_PLAN.md) 2단계의 준비 설계다. **구현·실행 검증 전 초안**이며 현재 런타임/저장 계약을 변경하지 않는다. 요구는 [최신 인수인계](TEMP_HANDOFF_2026-10-15_PARTY_AI.md)를 따른다.

## 현재 구조에서 바꿔야 할 경계

| 현재 코드 | 문제 | 후속 경계 |
| --- | --- | --- |
| [GameplayState](../src/core/exploration.hpp)의 단일 enemyInstance/hit/damage | 서로 다른 적의 공격·결과를 독립 소유할 수 없음 | 배우별 선택 행동·고정 대상·결과·완료 소유자 |
| [afterCombatAction](../src/core/gameplay.cpp)의 주인공→동료→현재 적 | 다른 전투가 현재 조우의 대기/종료에 종속 | 전역 라운드와 배우별 진행을 분리 |
| ActorCompletion의 player/enemy/partner bool | 같은 적의 이전 clip 또는 다른 적 완료를 구분할 수 없음 | 배우 ID와 해당 액션 ID를 함께 확인 |
| [Windows main](../src/windows/main.cpp)의 단일 enemyAnimator_ | 여러 적 전투를 동시에 표시하기 어려움 | 기존 actorAnimators_를 재사용할 수 있는지 확인하고 배우별 전투 clip을 연결 |

단순 HUD 수정·거리 require 삭제·현재 적을 바꾸는 방식으로 해결하지 않는다. 렌더 상태는 코어의 확정된 행동을 보여주며 피해·RNG·행동권을 자체 결정하지 않는다.

## 라운드·행동 계약

- 전역 라운드는 살아 있는 참여 배우의 행동권을 추적한다. 이동·공격·열매·대기는 하나의 행동이며 이동 후 같은 라운드에 추가 공격하지 않는다.
- 아군은 각각 자신의 대상을 선택한다. 통로 양쪽 전투는 같은 라운드에 시작/진행할 수 있어야 하며, 현재 적 한 개가 전체 전투의 소유자가 되어서는 안 된다.
- 목표 선정은 결정적인 배우 순서·동률 기준을 사용한다. 기존 적의 가까운 살아 있는 아군 선택과 동률 주인공 규칙을 보존한다.
- 공격 시작에서 대상·명중/급소·피해·RNG 진행·행동권을 함께 저장한 뒤 공개한다. 화면 재생 중에는 대상을 바꾸지 않는다.
- 공격/피격/기절의 완료는 해당 배우·액션 ID에만 적용한다. 다른 배우, 이전 액션, 중복 완료는 새 행동이나 추가 피해를 만들지 않는다.
- 한 적의 기절/승리 정리는 해당 적의 진행만 끝낸다. 나머지 아군/적의 미소비 행동은 유지한다. “기절 애니메이션 대기”를 전역 탐험/전투 중단으로 사용하지 않는다.
- 공격 중 피격·기절이 겹칠 때 기존 선공/이미 확정된 피해 규칙과 새 동시 표시가 충돌하지 않도록 회귀로 순서를 고정한다. 공격 결과를 화면 완료 순서에 따라 재추첨하지 않는다.
- 같은 시각에 들어온 완료는 안정된 배우 순서로 처리하고, 독립 액션들을 동일 update에서 반환/공개할 수 있는지 API를 검토한다. 단일 GameplayUpdate 때문에 나머지 사건이 누락되지 않게 한다.
- 명중80%, 아군 급소20%/적5%, 피해1/2,HP5·열매 회복2 등 기존 규칙을 임의 변경하지 않는다.

## 도주·추적·복귀

- 주인공: 회복 가능 여부와 합법 도주 경로를 판단한다. 막혔고 인접 적을 공격할 수 있으면 전투한다. 이동·공격 모두 불가하면 대기하고 다른 배우 행동 뒤 재평가한다.
- 동료: 진행 중 전투를 주인공 도주 때문에 취소하지 않는다. 전투 완료 뒤 복귀를 우선하고, 그 밖에는 가까운 추적/적 접근을 자신의 행동권으로 수행한다.
- 전투/복귀 중에는 동료가1칸 밖에 있을 수 있다. 모든 상태에서 지형·모서리·배우 비중첩을 유지하며 저장/복원도 허용한다.
- 직선으로 도달 가능하면 같은 행/열의 직선을 우선한다. 막히면 합법 경로를 찾으며 대각선 전체 금지나 단순 방향 배열 교체로 회피·모서리를 망가뜨리지 않는다.
- 수동 Reset·패배·정상 클리어만 기존 귀가 정책으로 연결한다. 목표 없음·경로 막힘·반복을 정상 클리어로 취급하지 않는다.

## 저장·복원 설계 확인 항목

새 배우별 진행을 저장해야 하므로 MDES8을 검토한다. **아직 MDES8을 구현/확정하지 않았으며 현재 쓰기는 MDES7이다.**

| 저장할 의미 | 복원에서 보장할 것 |
| --- | --- |
| 전역 라운드, 배우별 소비 행동권/의도 | 같은 라운드에 행동 재소비/누락 없음 |
| 액션 소유 배우·대상·고유 ID | 다른 액션/다른 배우 완료로 진행하지 않음 |
| 선택된 명중/급소/피해와 적용 여부 | 복원 뒤 RNG 재추첨·피해 이중 적용 없음 |
| 공격·피격·기절 진행과 시작/기한 | 중단·일시정지·timeout 뒤 합법 재생/완료 |
| 동료 전투/추적/복귀와 목표 | 떨어진 상태를 거부하거나 순간이동으로 덮지 않음 |

키는 run/floor/round/actor/action을 포함해 구분한다. 배열·대상 참조·시간·중복 키의 상한과 CRC·잘림 거부를 검증한다. 기존 snapshot prefix/enum을 무단 재해석하지 않는다.

MDES1~7은 기존 reader로 읽고, MDES7의 진행 중 공격은 저장된 단일 대상·결과·소비 행동권을 새 상태로 보존해야 한다. 공격 도중 무조건 Explore로 돌리거나 피해를 재추첨하지 않는다. 구형 fixture를 만들 때 새 block을 제거하지 않고 버전 숫자만 바꾸는 검사는 금지한다.

7층 전환은 전투 schema 이행과 별개로 package assetVersion과 floor 출처를 다룬다. 기존3층 저장의 패키지 선택·진행을 유지하고 새 탐험부터7층을 적용하는 전략을 먼저 검증한다.

좌표는 기존 companion fixture의24칸 폭을 기준으로 한다. 아래는 **실행할 검사 설계이며 실행 결과가 아니다.**

| ID | 입력·재사용 fixture | 판정 |
| --- | --- | --- |
| R01 직선 | 기존 follow: 주인공125=(5,5), 동료124, 아이템129=(9,5), 적 없음 | 125→126→127→128→129. 벽/점유가 추가되면 합법 우회 |

| R03 포위 | y=5 통로의 적123–동료124–주인공125–적126, 주인공HP1/열매0 | 자동 귀가0회, 공격 가능한 적과 전투. 전부 행동 불가 변형은 대기/재평가 |
| R04 양방향 | R03의 HP5, 적/아군 모두 미소비 행동권 | 양 아군의 서로 다른 적 공격과 각 적의 최대1회 행동. 실제 동시 애니메이션도 확인 |
| R05 한쪽 처치 | R04에서 왼쪽 적 remainingHits=1, 적중 고정 RNG | 왼쪽 기절 후 오른쪽 전투/피해/다음 라운드 지속 |
| R06 도주·복귀 | 주인공 저체력 도주, 동료는 전투 중 | 동료 전투 유지→처치→직선/막힘 합법 복귀. 거리>1 상태 저장 성공 |

재현 단계에서 이전 구현의 실패를 먼저 기록한다. 회귀가 실제로 실패했는지 확인하지 않은 채 “재현 완료”로 커밋하지 않는다. Windows는 기존 CSV에 라운드/배우/액션/대상/완료 ID를 연결해 코어 상태와 실제 표시를 대조한다.

## 구현 전 확인할 사항

선공과 서로 다른 전투의 동시 표시를 함께 만족하는 구체적 스케줄, MDES7 진행 중 전투의 이행, 같은 배우의 공격/피격 clip 경합은 고정 회귀를 실행하면서 최종화한다. 실행 환경 부재로 이 문서 작성 시 코드·테스트·자산·EXE를 변경하지 않았다.
